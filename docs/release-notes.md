## 本次更新（1.6.0）—— 换掉英文镜像，默认走中文数据源

> **一句话**：移除默认配置里的英文镜像 `rkw`（境外 Cloudflare、更新偏慢），
> 默认改用它抓取的那个中文查询器页面，并新增哔哩哔哩 Wiki 作为可选目录渠道。
> 老配置会自动迁移，**不需要手动改 config.json**。

### 为什么移除英文镜像

`rkw` 指向 `rocokingdomworld.org`：英文界面、托管在境外 Cloudflare（实测 419–590ms，经代理节点），
而且它自己还有一层缓存——换货后往往要等几分钟才更新。查证它的返回体时发现一行关键信息：

```json
"source": "https://www.onebiji.com/hykb_tools/comm/lkwgmerchant/preview.php?id=1&immgj=0"
```

也就是说，它只是中间层，真正的数据来自那个**中文**的「每日远行商人查询器」页面。
直连数据源可以少一层中转，也顺带解决"英文站"的问题。

### 新默认渠道：`onebiji`（中文查询器）

- **中文、免 Key、境内直连**，页面直接列出今天 4 轮的全部商品
- 每件商品都带：名称 / 价格 / 限购 / 图标 / 分类 / 描述 / **在哪些轮次售卖**（`show_1..show_4` 类名）
- 程序按轮次筛出本轮货架，`rounds` 语义与原来的 `rounds` 字段完全一致（全天商品的"全天"角标照常工作）
- 同一件商品会按轮次拆成多条（如"神奇的蛋"在第 1、3 轮各一条），解析时**按名称合并轮次**，
  不会像通用映射那样把重名条目丢掉
- 页面不返回 `status` / `expectedRound` / `nextRefresh`，这些用本地时间推算，
  因此不会误触发"轮次滞后"重试；换货后仍由既有的"假刷新识别"兜底

实测对账（同一时刻）：旧渠道返回"网兜球 / 暗星球 / 神奇的蛋"，新渠道解析后筛本轮同样是这 3 件，
价格与限购一致。

### 新增可选渠道：`bwiki`（哔哩哔哩 Wiki · 商店目录）

按你的要求把它做成了可选渠道，但**默认不填地址**，原因是实测结论：

- BWIKI（`wiki.biligame.com/rocom`）没有「远行商人」条目，也没有每轮货架接口
- 「商店一览」只有 110 家商店 / 1106 件商品的目录，页面原话是"商品价格会随版本调整，
  页面不再单独列出"，且没有轮次与刷新时间
- 商品行在 DOM 里也不与商店归组，连"远行商人卖哪几件"都无法可靠还原

所以选中它时程序会**明确报错**说明原因，而不是显示一份假货架。地址与启用方式写在它的配置说明里，
将来 Wiki 若开放结构化接口，改 `base_url` 即可接入。

### 兼容性

| 项 | 变化 |
|---|---|
| `provider` 默认值 | `rkw` → `onebiji` |
| 老配置迁移 | `provider: "rkw"` 自动改成 `onebiji`，`providers.rkw` 残留条目自动清理 |
| 降级顺序 | `official → cn_mirror → onebiji → bwiki → yxsr → shallow → custom` |
| 自建反代 `cn_mirror` | 现在先试 JSON、失败再按页面解析，**可以直接反代 HTML 页面**，不用写转换层 |
| 其他功能 | 轮次、全天商品、假刷新识别、慢速续试、通知去重全部不变 |

`yxsr` 渠道保留但标注为"历史渠道"：2026-10 实测它的证书已变成自签名，程序会按设计拒绝连接。
