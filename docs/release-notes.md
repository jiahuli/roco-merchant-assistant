## 本次更新（1.4.1）

### 修复：换货后无法识别新商品

**现象**：八点换货后，新上架的商品（如十二点的血脉药）不显示；上一轮的条件球却一直在。

**根因**（两个独立缺陷叠加）：

1. **接口有缓存，换货瞬间仍返回上一轮的货架**。旧实现只在 08:05 / 12:05 等固定时间点查一次，
   查到旧轮次数据也照常渲染，之后要等到下一个整点才再查——所以整轮都看不到新品。
2. **完全没有使用 `rounds` 字段**。接口用 `rounds` 标注售卖轮次：`[1,2,3,4]` 是四轮都卖
   （条件球、棱镜球这类），`[3]` 是只在第 3 轮卖。旧版把两者一视同仁，界面上无法区分
   "正常地一直在"和"该下架却没下架"。

**修复**：

- 解析 `rounds`，`MerchantItem.is_all_day` 判定全天商品；卡片显示「全天」角标，
  货架统计写明「其中 N 件全天在售」，不再把全天商品误认为没刷新
- 解析 `expectedRound`，与 `round` 比对得出 `is_round_lagging`（接口仍在上一轮）
- 滞后时自动重试：按 **30 / 60 / 120 / 180 / 240 秒** 依次重试，拿到新一轮数据即停；
  耗尽后状态栏标记「数据滞后」，可手动刷新
- 防御性过滤 `filter_by_round()`：剔除 `rounds` 明确不含当前轮的条目，
  防止上游把旧轮次商品混进本轮
- 状态栏与货架标题都会提示「接口仍是第 1 轮（应为第 2 轮），正在重试」

设置里新增开关「换货后自动校验（接口还没刷新时持续重试）」，默认开启。
