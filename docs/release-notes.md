## 本次更新（1.4.2）

### 修复：卡在两件全天商品上，新物品刷不出来

**现象**：接口数据更新延迟时，界面一直只有条件球 / 棱镜球这类全天在售的两件商品，
该轮的新商品始终不出现；手动刷新也没用，要等到下一个定时点才可能恢复。

**根因**：1.4.1 的"换货校验"只看接口自报的轮次是否落后（`round_index < expected_round`），
可是上游还有两种"假刷新"让它永远看不出问题：

1. `round` 字段已经刷成新轮次，`items` 却还是上一轮的货架；
2. 部分渠道根本不返回 `round`，程序只能用本地时间兜底，算出来的轮次永远"不落后"。

这两种情况下校验判定为"数据正常"，于是不重试。再叠加 `filter_by_round()` 会把
`rounds` 不含当前轮的旧商品剔掉，货架上就只剩下 `rounds=[1,2,3,4]` 的全天商品——
界面上正好是那两件，而且内容一直不变，看上去像"这轮就卖这些"。

**修复**（新增 `freshness.py`，把判定从"只看轮次"改成"轮次 + 货架内容"）：

- **内容比对**：当前只剩全天商品、且与上一次结果完全相同时，判定为"接口还没换货"，
  按可配置的间隔延后重取 —— 默认 **5 分钟**、最多 **3 次**；
  两个参数都在 设置 →「定时查询」里可改（`recheck_delay_seconds` / `recheck_max_attempts`）
- **货架缩水**：上次还有本轮商品、这次只剩全天商品（旧轮次被过滤掉了），同样触发重取
- **冷启动也能判断**：上一份货架指纹写进 `state.json`，重启后仍可与历史比对
- **不重复骚扰**：同一份内容在同一轮次放弃过一次后不再重取；跨轮或内容变化后自动恢复
- **原有轮次重试不变**：接口自报轮次落后时，仍按 30/60/120/180/240 秒阶梯重试，
  带本轮商品的正常货架完全不受新判据影响
- 重取次数用尽后，状态栏 / 药丸 / 货架标题同时标注「只有 N 件全天商品，数据可能未更新」，
  而不是静默显示成正常数据

### 其它

- `MerchantSnapshot` 新增 `dropped_count`，日志会写明"剔除旧轮 N 件"，
  以后再遇到"为什么只有两件"可以直接从日志看出答案
- 重取排程新增忙时退避：查询正在进行时不会把重取链悄悄丢掉，而是稍后再来
- `state.json` 改为合并写入，通知去重与货架指纹互不覆盖
- 设置面板对重取节奏做输入校验（间隔 30–3600 秒、次数 0–10，0 = 关闭该判据）
- 自测 157 → 198 项（新增新鲜度判据、重取端到端收敛、设置面板校验）
