## 本次更新（1.4.3）

### 新增：重取用尽后，由你决定下一步

1.4.2 修好了"卡在两件全天商品上"，但次数用尽后只有一种收尾：标记「数据滞后」、
等下一个定时点。现在把这个决定权交给用户，**默认行为完全不变**。

设置 →「定时查询」→「次数用完后」：

| 选项 | 行为 | 适合谁 |
|---|---|---|
| **放弃本轮**（默认） | 本轮不再自动请求，保留接口数据并标注「可能未更新」，等下次定时或手动刷新 | 大多数情况；请求量最小 |
| **转入慢速续试** | 按「慢速间隔」（默认 30 分钟）继续悄悄试，换轮 / 内容变化 / 达到慢速上限 / 手动刷新即停 | 长时间挂机、希望换货后尽快看到新品 |

配套两个可调项：慢速间隔 300–3600 秒、慢速上限 0–20 次（0 = 不限）。
所有取值都在设置界面做了校验，配置被手改成非法值时会自动回落默认，不会让程序失灵。

改动的边界很克制：**只在"常规次数用尽"这一个分支分叉**，判据（轮次落后 / 只剩全天商品 /
本轮商品消失）、常规阶梯（30/60/120/180/240 秒）与界面渲染都没动。

### 新增：一键同步到 GitHub

每次改完都要手动 `git add` + 提交 + 推送，容易顺手把 `dist/` 的 exe、`__pycache__` 带上，
或者忘了跑自测就推。新增 `tools/publish.py` + `sync.bat`，把流程固定成四步：

```bat
sync.bat                                    :: 自测 → 收集 → 提交 → 推送
sync.bat -m "fix(x): 修好了" --tag v1.4.3    :: 指定信息、顺便打标签
python tools/publish.py --dry-run           :: 只看会提交哪些文件
python tools/publish.py --push-only         :: 只推送已有提交
```

- **自测门禁**：自动挑一个带 `tkinter` 的解释器跑 `selftest.py`，不死板依赖当前 `python`
- **白名单收集**：只提交源码 / 文档 / 构建脚本 / 图标，跳过构建产物、缓存、日志与 `.github/`
- **失败可续**：推送失败时本地提交仍在，网络恢复后 `--push-only` 即可
- 同步 ≠ 发版：只推源码与文档，exe 仍走 `build_exe.bat` + `tools/release.py`

流程与排除规则写进了 `docs/DEVELOPMENT.md` 第 8 章，可配置项全景写在第 7 章。
