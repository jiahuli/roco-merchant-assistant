## 本次更新（1.8.0）—— 历史货架、按物品提醒、已购标记、跨日修复

### 新增：历史售卖物品

换货后就再也拿不到上一轮了——数据源只给"当前这一轮"。现在每次查询都会按
「日期 + 轮次」记一份，保留最近 7 天（最多 28 轮）。

- **默认折叠**，标题上写明有几轮；展开后按时间倒序：最新的 **20:00 在最前**，
  然后 16:00 / 12:00 / 08:00
- **保留全天在售商品**：条件球、棱镜球这类四轮都卖的东西本来就是那一轮货架的一部分，
  历史里不做剔除
- 同一轮重复查询（重试、手动刷新）只更新内容，不会堆出一堆重复记录
- 打烊、空货架不会被记成一条"什么都没卖"的假历史
- **没有历史时不能展开**：展开按钮为禁用态（「暂无历史」），标题行也不响应点击
- 设置 →「历史记录」可以关闭该功能（不写盘、不显示），或把存放目录改到别处；
  改目录时已有记录自动迁移，目录不可写会回退默认位置并提示

### 新增：按物品选择通知

以前只能按品质粗筛（史诗 / 传说以上），想单独盯"国王球"会把同品质的球一起通知；
而"可可果球"这类限时活动道具品质不高，永远进不了阈值。现在两者并行：

- 设置 →「通知提醒」→「关注物品」→「选择…」，勾选要提醒的物品
- **关注物品不看品质**，上架就提醒；原来的品质阈值继续生效，两条规则取并集
- 清单可更新，来源有三处：
  1. Wiki 抓取（`商店一览` 的常驻条目 + 正文提到远行商人的条目，含图标）
  2. **本机实际见过的商品自动累积**——只要上过一次架，就能被选到
  3. 手动添加（新活动道具名字已知、还没上架时用）
- 图标优先用缩略图：同一物品同时有 100px 小图和 Wiki 原图时选小的，省流量也省磁盘

> 为什么不是"从 Wiki 抓一份完整清单"：实测 BWIKI 没有轮换货架，`商店一览` 里
> `#2002 远行商人` 只登记 1 件常驻商品，正文提到远行商人的条目只有 3 个。
> 清单必须能自己长大，否则新道具永远选不到。

### 新增：已购买标记

- 卡片右上角「○ 标记」，点一下变「✓ 已购」，商品自动移到下方独立的「已购买」区
- 已购卡片整体压暗、价格变灰，不再抢注意力；再点一次即可撤销
- 标记按**轮次**记录：换货后自动失效。下一轮同样的商品如果又上架，应该重新提醒，
  而不是继承上一轮的勾选

### 修复：24 点后仍显示昨日商品

**现象**：过了 00:00，界面还列着昨天 20 点那一轮的货架，没有任何提示说明它是旧的。

**根因**：数据源在打烊后并不会清空，页面仍挂着 20 点那一轮；而轮次计算在
00:00–08:00 返回 0，`filter_by_round()` 见到假值会**原样返回全部条目**，
于是昨日货架一路穿到界面上。上游 JSON 渠道更直接：缓存里的 `status` 还写着 `open`。

**修复**：营业时间是本地就能确定的事实，不需要相信接口。三层同时兜底：

1. `providers` 在非营业时段把 `items` 清空、`status` 强制为 `closed`（页面与 JSON 两条路径都改）
2. 主窗口渲染前再判断一次当前时间，非营业时段一律按"已打烊"展示
3. 悬浮窗同样不列商品——否则它会成为漏网之处

打烊占位文案也补了一句"打烊期间不显示上一轮的货架"，避免被误读成"正在补货"。

### 界面微调

- 「○ 标记 / ✓ 已购」按钮加大（字号 8→9、内边距加倍），并加了悬停反馈，
  不再是一行看起来不可点的小字
- 历史区域的展开控件从一行小字换成 104×30 的圆角按钮（「展开历史 / 收起历史」），
  整行标题也可以点
- 悬浮窗标题栏的 `⟳` / `◉` / `–` / `✕` 统一放大（标题栏 34→38px），点击区域约 30px
- **展开后的历史不再是纯文本**：复用主界面的商品卡片（图标、珍惜度色条、中文价格、
  内边距与圆角全部一致），一眼就能和"当前的货架"对上

### 发行版清理

多次发版间隔过短（同一天连发、甚至间隔十几分钟），Releases 页已经不好读。
1.8.0 发布时会按「被下一版在 6 小时内取代」的规则清理过渡版本（如 1.2.0、1.4.1），
只保留每个时间段的最终版；被清理版本对应的 tag 仍然保留在代码历史里。
**这一步与上传同批执行，需维护者确认后才动。**
