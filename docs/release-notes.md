## 本次更新（1.7.0）—— 修复大额价格被截断，悬浮窗可直接取数

### 修复：160000 显示成「十六」

**现象**：国王球、水系血脉秘药这类售价 `160000` 的商品，界面上显示成「十六」而不是「十六万」；
更隐蔽的是它们同时掉到「普通」珍惜度，**传说 / 史诗物品不再弹通知**。

**根因**：问题不在数字转换，而在价格解析。数据源页面把价格写成简写单位：

```
<em class="shop_price">价格：16w </em>
```

解析正则只抓 `[0-9]`，把 `16w` 读成了 `16`；`to_chinese_number(16)` 自然输出「十六」。
`numerals.to_chinese_number()` 本身是正确的——`160000 → 十六万` 已单独验证。

**修复**：

- `providers._to_int()` 现在认识 `万 / w / W / 亿 / 千 / k / K`，并支持小数（`1.6w` → 16000）；
  `16w`、`16万`、`1.6w`、`160,000`、`1000 万` 都有测试覆盖
- 页面价格正则改为抓整段文本，交给 `_to_int()` 统一换算，不再自行用 `[0-9]` 截断

**影响范围**（修复前）：

| 受影响 | 表现 |
|---|---|
| 价格显示 | 中文读法「十六」、原样「16 洛克贝」，与游戏内差 10000 倍 |
| 珍惜度推断 | `rarity.infer_rarity()` 按价格分层，160000 的传说物品被判成「普通」 |
| 通知 | 由珍惜度阈值决定 → 该提醒的物品被静默漏掉（影响最大的一环） |
| 波及渠道 | 所有走 `_to_int()` 的路径：页面解析、通用 JSON 映射、自建反代；纯数字价格不受影响 |

### 新增：悬浮窗「⟳ 立即获取」

以前要看最新货架，必须打开主窗口点「立即刷新」。现在悬浮窗标题栏多了一个 `⟳`：

- 点一下直接拉一次数据，**不需要打开主窗口**（主窗口藏在托盘里也可以）
- 取数中按钮变成「…」，结果回来自动复位，并刷新列表与「更新于 HH:MM」
- 复用主窗口的取数链路（线程池 / 结果泵 / 去重 / 通知），悬浮窗不另起一套网络逻辑
- 主窗口正在查询时点它不会重复发请求（由 `_loading` 拦下，按钮 8 秒兜底复位）
- 收起成横条后按钮仍在标题栏，随时可用

### 验证

- 自测 252 → **273 项**全过；新增：价格单位换算、页面 `16w` 解析、稀有度恢复、
  按钮状态机（点击/取数中/不重复触发/复位/收起后可用）、**隐藏主窗口取数端到端**
- 实测数据源：国王球 `16w` → `160000` → 「十六万」/ 传说；水系血脉秘药同；网兜球等纯数字价格不变
- 顺手修了两个会随钟点漂移的测试断言（按当前轮过滤的计数、回调与线程的时序）
